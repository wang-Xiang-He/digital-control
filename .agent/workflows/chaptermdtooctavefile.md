# Antigravity Workflow：MD → MATLAB / IPYNB 教學程式碼生成規範

## 目的

這個 workflow 的輸入是一份已經寫好的教學 Markdown（`.md`）檔案。

請以「原 MD 是教學內容，IPYNB 是可直接操作、可直接學習的版本」為原則，完整掃描整份 MD，將其中出現的 MATLAB 程式碼、函數、語法、數學表示法與概念，轉換並補充成對應的 `.ipynb`。

必要時另外產生對應的 `.m` 檔案，讓使用者可以直接在 MATLAB 執行。

重點不是只把 MD 裡的 code 複製進去，而是要把「看得懂這段 code 所需要的背景知識」一起補齊。

---

# 輸入

輸入檔案：

- 指定章節的 `.md` 教學檔案

使用者已經準備好 MD，因此不要重新發明一份全新的教學內容。

請以原始 MD 為主要依據，保留原有章節順序、教學邏輯與內容精神，再補充程式碼與解說。

---

# 輸出

至少產生：

1. 對應的 `.ipynb`
2. 對應的 `.m`

輸出檔名應與原始 MD 具有一致且容易對應的名稱。

例如：

```text
chapter_03.md
chapter_03.ipynb
chapter_03.m
```

---

# 核心要求：完整掃描 MD

請先完整讀取整份 MD，再開始生成，不要只看前幾段或只處理有明顯 code block 的部分。

必須逐段檢查：

- 標題
- 段落
- 數學公式
- MATLAB 程式碼
- 函數呼叫
- 變數定義
- 向量 / 矩陣表示法
- 單位
- 圖形繪製
- 系統建模
- 參數設定
- 結果解讀
- 範例題
- 練習題

掃描完成後，再決定 IPYNB 要建立哪些 Markdown cells 與 Code cells。

禁止只根據關鍵字抽取少數程式碼，必須理解整份 MD 的教學流程。

---

# 掃描時要同時檢查：MD 是否「只寫出公式名稱，卻沒解釋意義」

完整掃描不是只找出「有哪些公式、有哪些 code」，還必須針對**每一個重要公式**檢查：

> 這個公式除了被列出來、給了一個名稱或編號之外，MD 有沒有實際解釋它的意義？

常見的「只有名稱、沒有意義」的症狀：

- 只寫「六大設計步驟」「四項控制準則」這類條列標題，每項只有一句話帶過，沒有說明「為什麼需要這一步」「這個準則具體在測量什麼」
- 只寫出公式本身（例如 $G_p(s)=\dfrac{1}{Js^2}$），沒有回答「這是什麼系統」「$J$、$s$ 各自代表什麼」「為什麼分母長這樣」
- 提到一張圖（如方塊圖、流程圖）只說「如下圖所示」，卻沒有描述圖中訊號怎麼流動、每個方塊在做什麼
- 引用了書中其他章節或前置知識的名詞（例如「疊加原理」「取樣週期」），但沒有在本章脈絡下說明它的意思

如果掃描時發現有這種段落，**不能直接把公式原封不動塞進 IPYNB、假裝已經完成教學任務**。必須依照 `chapterpdftomd.md` workflow 所定義的「七個問題」框架，為該公式補齊意義：

1. 它是什麼？
2. 為什麼需要它？
3. 公式怎麼來的（推導）？
4. 公式中每個符號代表什麼？
5. 這個公式的物理意義是什麼？
6. MATLAB 要怎麼寫？
7. MATLAB 程式和公式怎麼對應？

補充這些說明時：

- 優先寫進 IPYNB 對應段落前後的 Markdown cell（這是本 workflow 主要負責的產出）。
- 若同一份 `.md` 之後還會被其他章節或讀者直接單獨閱讀（不透過 IPYNB），建議同時回頭補強 `.md` 本身，讓 `.md` 也能獨立成立、不必依賴 IPYNB 才看得懂——但仍要遵守下方「補充內容的界線」：只補意義、不改公式、不改例子的物理設定、不捏造教材沒有的內容。
- 這不是「重新發明一份教材」，而是把 MD 原本就隱含、但沒寫出來的意義講清楚；若真的完全無法從上下文推斷出意義（例如符號從未定義、無法確認物理量為何），則在 Markdown 中明確標註「原始 MD 未定義此符號，以下為依上下文合理推斷」，而不是悶不吭聲跳過。

**判斷基準**：完成後自問——如果讀者只看得懂國高中數學與基礎物理，讀完 IPYNB 對應段落，能不能不查任何外部資料就答出「這個公式在幹嘛、為什麼會長這樣」？答不出來就代表補充得還不夠。

# IPYNB 的定位

IPYNB 不是單純的「程式碼展示檔」，而是一份可以邊看邊執行的教學 Notebook。

因此每一段 MATLAB code 都要盡可能搭配說明。

例如 MD 中出現：

```matlab
tf([1], [J 0 0])
```

不能只在 IPYNB 放：

```matlab
tf([1], [J 0 0])
```

必須補充至少以下資訊：

- `tf()` 是什麼
- `tf()` 的用途
- `[1]` 代表什麼
- `[J 0 0]` 代表什麼
- 為什麼係數要寫成 `[J 0 0]`
- 向量中的數字順序代表什麼
- 這個向量如何對應到分母多項式
- 如果分母是 `J s^2`，為什麼 MATLAB 要寫成 `[J 0 0]`
- 至少給出一個簡單的對比例子

例如應該能讓初學者理解：

```text
[J 0 0]
```

代表多項式係數：

```text
J*s^2 + 0*s + 0
```

因此如果傳遞函數是：

```text
1 / (J*s^2)
```

MATLAB 就會將分母係數表示為：

```matlab
[J 0 0]
```

不要假設讀者已經知道這件事。

# MATLAB 函數介紹要求

凡是 MD 或生成的 code 中第一次出現重要 MATLAB 函數，都要在 IPYNB 中補充簡短說明。

例如：

```matlab
tf()
step()
impulse()
lsim()
plot()
grid()
title()
xlabel()
ylabel()
legend()
feedback()
series()
parallel()
ss()
```

每個函數依實際需要說明：

1. 函數用途
2. 基本語法
3. 參數意義
4. 回傳值 / 產生的物件
5. 一個最小可執行範例
6. 若容易搞混，補充常見錯誤

不需要對 MATLAB 每一個函數都做百科全書式介紹，只需要介紹「理解本章內容所需要的部分」。

---

# MATLAB 語法補充要求

除了函數本身，也要解釋初學者容易不懂的語法。

例如：

## 向量

```matlab
[1 2 3]
```

說明這是 row vector。

## 分號

```matlab
J = 10;
```

說明 `;` 通常用來抑制 Command Window 的輸出。

## 括號

說明 `()`、`[]` 在 MATLAB 中用途不同。

例如：

```matlab
A(1,2)
[1 2 3]
```

## 次方

```matlab
s^2
```

## 多項式係數表示

```matlab
[3 5 2]
```

代表：

```text
3s^2 + 5s + 2
```

這類內容要視整份 MD 實際出現的 code 自動補充。

---

# 「先解釋，再執行」原則

如果一段 code 對初學者而言不是立即可理解的，不要直接丟給使用者執行。

建議 Notebook 結構：

```text
Markdown：概念說明
↓
Markdown：這段 MATLAB 語法在做什麼
↓
Code：最小範例
↓
Markdown：執行結果應該看到什麼
↓
Code：正式範例
↓
Markdown：結果分析
```

---

# IPYNB Cell 規則

請盡量使用以下 cell 結構：

### 1. 章節標題 Markdown

對應 MD 原本的章節標題。

### 2. 概念 Markdown

簡要說明該段理論。

### 3. MATLAB 語法 Markdown

說明該段 code 中使用的重要 MATLAB 語法與函數。

### 4. Code Cell

放可以直接執行的 MATLAB code。

### 5. 結果 / 解讀 Markdown

說明執行後應該看到什麼，以及它和理論的關係。

### 6. 必要時加入練習 Code Cell

如果 MD 中有範例題或容易理解的變形，可以加入簡短練習。

---

# Code Cell 的要求

所有 Code Cell 儘量做到：

- 可以單獨理解
- 變數命名清楚
- 必要參數有註解
- 不依賴前面沒有宣告的神祕變數
- 不任意使用使用者環境中不存在的檔案
- 優先使用 MATLAB / Control System Toolbox 的標準功能

如果程式依賴特定 Toolbox，必須在 Markdown 中註明。

例如：

```text
需要 Control System Toolbox
```

# `.m` 檔案要求

`.m` 檔案的目的與 `.ipynb` 不同：

- `.ipynb`：教學、解釋、互動
- `.m`：集中、乾淨、可直接執行

因此 `.m` 可以移除大量教學文字，但要保留必要註解。

建議結構：

```matlab
%% Chapter 1
% 簡短說明

%% Parameters
J = 10;

%% Transfer Function
sys = tf(1, [J 0 0]);

%% Step Response
step(sys);
grid on;
```

如果原 MD 有多個彼此獨立的範例，可以用 `%%` 分段。

---

# 不要遺漏數學與 code 的對應

如果 MD 中寫的是：

```text
G(s) = 1 / (Js^2)
```

而 code 是：

```matlab
tf(1, [J 0 0])
```

IPYNB 必須把兩者明確連起來：

```text
數學式
    ↓
分母多項式
    ↓
多項式係數向量
    ↓
MATLAB tf() 輸入
```

也就是：

```text
1 / (Js^2)
        ↓
Js^2 + 0s + 0
        ↓
[J 0 0]
        ↓
tf(1, [J 0 0])
```

這種「公式 → 程式碼」的轉換要優先補充。

# 對每段 code 做「這行在幹嘛」檢查

完整掃描 MD 後，逐段確認：

> 使用者如果完全沒看過 MATLAB，是否知道這行在做什麼？

如果答案是否定的，就在 IPYNB 補充解說。

例如：

```matlab
sys = tf([1], [J 0 0]);
```

至少要拆開解釋：

```text
sys
↓
用來存放建立好的傳遞函數系統
```

```text
tf()
↓
建立 Transfer Function（傳遞函數）模型
```

```text
[1]
↓
分子多項式係數
```

```text
[J 0 0]
↓
分母多項式係數
↓
J*s² + 0*s + 0
```

# 避免隱含知識

不要假設使用者知道：

- MATLAB vector 是什麼
- polynomial coefficient vector 是什麼
- transfer function 是什麼
- `tf()` 是什麼
- Control System Toolbox 是什麼
- `s` 和時間 `t` 的角色差異
- row vector / column vector 的差異
- MATLAB 函數的輸入順序
- `[]` 和 `()` 的差別

如果這些概念在本章出現，而且沒有被 MD 充分解釋，就補到 IPYNB。

# 補充內容的界線

補充的目的是讓使用者「看懂原 MD」，不是把整份教材改寫成另一份教材。

因此：

- 保留原本教學內容
- 不任意改變原公式
- 不任意改變原範例的物理意義
- 不任意修改原參數
- 發現原 code 有疑似錯誤時，不要默默改掉
- 若能合理判斷是錯誤，請在 Markdown 加註「原始 MD 疑似存在問題」並說明原因

**注意**：補齊「公式只有名稱、沒有意義」的說明（見前面「掃描時要同時檢查」一節）**不算違反這條界線**。解釋一個公式是什麼、為什麼需要它、符號代表什麼，並不會改變公式本身、不會改變範例的物理設定、也不會修改參數——這是把原作者隱含但沒寫出來的意義講清楚，而不是另外發明一套教材。真正要避免的是：擅自改寫公式推導的邏輯順序、置換範例情境、或加入原教材沒有出現過的新物理系統/新例題。

# 發現 MATLAB code 有問題時

如果原 MD 出現：

```matlab
tf([1], [J 0])
```

但依照前文數學式應該是二階分母：

```text
Js^2
```

不要直接替作者重寫成正確答案而不說明。

應該：

1. 保留原始寫法的資訊
2. 指出問題
3. 說明正確形式應為什麼
4. 提供修正版 code

例如：

```text
原始寫法：tf([1], [J 0])

這代表分母 J*s + 0，而不是 J*s^2。
若原本數學式是 1/(J*s^2)，則應寫成：

tf([1], [J 0 0])
```

---

# 公式轉 MATLAB 的要求

遇到數學公式時，盡量補一個「如何轉成 MATLAB」的小節。

例如：

```text
G(s) = (2s + 3) / (4s^2 + 5s + 6)
```

應對應：

```matlab
num = [2 3];
den = [4 5 6];
sys = tf(num, den);
```

並解釋：

```text
[2 3]
→ 2s + 3

[4 5 6]
→ 4s² + 5s + 6
```

# 重要原則

不要把任務理解成：

> 「把 MD 裡的 MATLAB code 找出來，塞進 IPYNB。」

而是：

> 「讀懂完整 MD，建立一份與原 MD 一一對應、可以直接執行，而且連 MATLAB 基礎語法都補充完整的 IPYNB。」

因此，遇到任何程式碼，只要存在「使用者可能會問這是在幹嘛？」的可能，就應優先補充解釋。

特別是：

```matlab
tf([1], [J 0 0])
```

這類程式碼不能只當作黑盒函數使用，必須讓使用者理解：

```text
tf
↓
Transfer Function

[1]
↓
分子多項式係數

[J 0 0]
↓
分母多項式係數
↓
J*s² + 0*s + 0
```
